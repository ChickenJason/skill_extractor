# 自我标注器重构候选：从 Token/BIO 到极端多标签 Span 集合

## 约束与问题定义

- 保留现有内联 `<skill>...</skill>` 提示词和五次独立采样。
- 不再把 span 转换为 Token/BIO，也不再按 Token、B、E 分别投票。
- 正式输出仍是原句中的一个无序、非重叠技能 span 集合。
- 当前任务没有固定技能 taxonomy，因此不能直接套用“全局技能名称为标签”的传统 XMLC。
- 推荐把任务定义为 **instance-wise span XMLC**：对长度为 `m` 的句子，潜在标签空间是所有字符区间
  `L_x = {[s,e) | 0 <= s < e <= m}`，规模为 `O(m^2)`；模型每次只稀疏提出少量正标签。

## 当前证据

- v4.2 adaptive run：326 句中 accepted 214、negative 89、review 15、abstained 8。
- 当前正式覆盖率为 303/326 = 92.94%，补采样后人工复核率为 7.06%。
- 现有 476 个 `accepted` candidate 中，16 个分布在 13 个 accepted 句子里，没有达到对应的完整
  exact-span 支持阈值。这说明 Token 覆盖票、左边界票和右边界票可能由不同样本组合成
  “Frankenstein span”。
- 仅使用 exact-span 多数票的离线探针得到：accepted 204、negative 89、review 21、abstained 12。
  它会把 13 个当前 accepted 句子降为 review，但也会把 3 个当前 review 句子错误升为 accepted，
  原因是它静默丢弃了被多个边界变体分散支持的第二个技能。因此不能只做 exact vote。

## 候选 1：朴素 Exact-Span XMLC 多数投票

- **核心主张**：每个 `[start,end)` 是一个独立标签，按完整区间出现次数投票。
- **可能贡献**：彻底消除 BIO 和跨样本拼接边界。
- **最小实验**：直接重放当前 `parsed/samples.jsonl`，采用 4/5、7/10 exact 阈值。
- **预期证据**：不再产生完整支持不足的 accepted span。
- **风险**：不同边界变体会分散票数，且可能静默遗漏一个有多数“存在证据”但无 exact 多数的技能。
- **失败模式**：句子被部分标注后错误 accepted。

## 候选 2：重叠族发现 + Exact-Span 决策的两阶段 XMLC（主方案）

- **核心主张**：模仿 CMAS 的 mention/type 两阶段投票。第一阶段用重叠区间族判断“这里是否稳定存在
  一个技能提及”，第二阶段才用 exact `[start,end)` 标签决定边界。
- **可能贡献**：同时避免 BIO 拼接和朴素 exact vote 的静默漏标。
- **最小实验**：在现有 parsed spans 上构建区间冲突图，计算 family support 与 exact support，
  无需新增 API 调用。
- **预期证据**：13 个 Frankenstein accepted 被拦截；朴素 exact vote 错误放行的 3 个句子仍进入 review。
- **风险**：链式重叠可能把相邻技能放入同一族，需要“先解释高置信标签、再检查残余族”。
- **失败模式**：过度聚类导致 review 率过高。

## 候选 3：完整标签集合的 Medoid 共识

- **核心主张**：不逐标签投票，选择与其他采样结果平均集合距离最小的一个原始预测集合。
- **可能贡献**：输出一定来自某个真实模型样本，不会合成从未出现过的标签集合。
- **最小实验**：用 exact-span Jaccard 或对称差选择 5/10 个样本中的 medoid。
- **预期证据**：完全杜绝 Frankenstein set，结构简单。
- **风险**：一个 medoid 样本仍可能包含低频错误；不能充分利用跨样本稳定但分散的正确标签。
- **失败模式**：长句中少数偶然相似的低质量集合胜出。

## 候选 4：全局 Span Set Packing / 加权区间调度

- **核心主张**：把所有 exact span 标签视为候选，用票数、长度和冲突惩罚形成全局目标，选择最大权重
  非重叠集合。
- **可能贡献**：显式解决 overlapping span，而非按局部规则逐一筛选。
- **最小实验**：候选权重使用 exact vote；比较 greedy、weighted interval scheduling 和当前决策。
- **预期证据**：对长句、多技能和包含关系更稳定。
- **风险**：优化器总会给出答案，可能把不确定性隐藏为确定输出。
- **失败模式**：选择数学上最优、语义上错误的部分集合。

## 候选 5：LLM Proposal → Verifier 两代理 XMLC

- **核心主张**：第一轮沿用当前采样生成候选标签；第二个 verifier 针对候选 span 做独立二元/多标签核验。
- **可能贡献**：将生成偏差与验证偏差分离，接近 CMAS 的协作代理思想。
- **最小实验**：只对 review/abstained 句的候选族请求一次结构化验证。
- **预期证据**：在不全量增加成本的情况下解决边界族分歧。
- **风险**：需要新提示词或新输入合同；同模型 verifier 可能继承相同偏差。
- **失败模式**：额外成本增加，但校准和 exact F1 没有改善。

## 候选 6：语料级 Surface-Form 标签库 + XMLC 检索短名单

- **核心主张**：把第一轮高置信技能原文短语作为全局标签库，对新句先检索候选标签，再做多标签分类。
- **可能贡献**：逐步把开放抽取转成可扩展的全局 XMLC。
- **最小实验**：从 accepted spans 建标签库，对 review 句做字符串/embedding Top-K 检索。
- **预期证据**：高频技能和工具名称的稳定性提高。
- **风险**：新技能无法进入旧标签库；同义词、变体和重复表面形式造成标签爆炸。
- **失败模式**：召回被候选库上限锁死。

## 候选 7：Canonical Skill Taxonomy XMLC + 文本 Grounding

- **核心主张**：先预测大规模标准技能标签，再在原句中定位 supporting span。
- **可能贡献**：直接连接技能规范化和下游技能库。
- **最小实验**：需要外部 taxonomy、标签描述、负采样和 grounding gold。
- **预期证据**：canonical-label F1 与 mention grounding F1。
- **风险**：当前项目没有 taxonomy，且原提示词只输出原文 span。
- **失败模式**：标签预测正确但文本无法精确落地，或 taxonomy 外技能全部漏失。

## 候选 8：Start/End 边界标签的笛卡尔积分类

- **核心主张**：分别对所有字符起点和终点做多标签分类，再配对形成 span。
- **可能贡献**：避开 Token/BIO，同时保留边界证据。
- **最小实验**：统计采样中的 start/end 票，再用合法配对打分。
- **预期证据**：边界投票可解释，复杂度低于枚举所有 span。
- **风险**：仍会把来自不同样本的 start/end 拼接成从未出现过的 span，本质上保留了当前缺陷。
- **失败模式**：继续产生 Frankenstein span。

## 候选 9：概率式弱标注聚合

- **核心主张**：对 exact span 标签估计潜在真值与“标注器可靠度”，使用 Dawid–Skene/EM 或贝叶斯模型。
- **可能贡献**：从硬阈值升级为概率校准，可输出风险—覆盖曲线。
- **最小实验**：把不同采样位置、恢复状态或温度视为弱标注源。
- **预期证据**：Brier/ECE、accepted-only precision 和 coverage 改善。
- **风险**：同一模型的重复采样并不是独立标注器，326 句也不足以稳定估计复杂参数。
- **失败模式**：得到看似精确但失真的置信概率。

## 候选 10：成本感知的级联 XMLC

- **核心主张**：先做 3 次采样；高置信 exact 集合立即结束，中置信进入 5 次，残余冲突进入 10 次或 verifier。
- **可能贡献**：将当前固定 5+5 改为按多标签不确定性分配预算。
- **最小实验**：使用现有 5/10 样本离线模拟在 3、5、10 次时的决策与成本。
- **预期证据**：相同 accepted precision 下减少 API 次数和 Token。
- **风险**：早停阈值若校准不足，会把前三次偶然一致当作确定结果。
- **失败模式**：成本降低但错误接受率上升。

## 初步选择

- 主方案：候选 2。
- 第一备选：候选 10，作为主方案稳定后的成本优化。
- 第二备选：候选 5，只用于主方案仍无法解决的 residual review。
- 候选 1 与候选 3保留为必要基线，不作为最终系统。
