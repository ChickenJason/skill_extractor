## 排序理由

主方案唯一同时满足以下条件：

- 不改现有提示词；
- 不增加 API 调用；
- 可以直接重放已有 parsed spans；
- 从定义上阻止跨样本拼接 span；
- 不会像朴素 exact vote 那样静默丢掉被边界变体分散支持的技能；
- 能延续 CMAS 的 label-level 与 sample-level 置信筛选思想。

成本级联虽然总分高，但它依赖核心共识已经正确校准，因此只能在主方案之后实施。Verifier 方案适合
处理最后的 residual review，但不是零成本 MVP。
